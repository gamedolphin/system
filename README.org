* Introduction
#+HTML:    <div align="center"><img src="./.github/images/screenshot.png" width="100%" /> </div>
Hello! Welcome to my literate file that describes (and generates) the configuration for all my computers.

For people who are confused, this file has a bunch of source blocks that are then put into individual files using emacs+org's tangle mode.

Once the files are generated, they are converted into an immutable system configuration using nixos.

This repository consists of configuration for my main machine
- =smallbox= -- my wfh computer and main laptop
- =macbox= -- work computer for builds etc

To generate the actual nix files, you need to open this file in emacs and then execute =M-x org-babel-tangle=.

Or run the following from the command line
#+begin_src bash :tangle no
  emacs README.org --batch -f org-babel-tangle
#+end_src

Once the nix files are ready, you can deploy using
#+begin_src bash :tangle no
  nixos-rebuild switch --flake .#<machine>
#+end_src

To update the mac machine
#+begin_src bash :tangle no
  nix run github:serokell/deploy-rs -- .#macbox
#+end_src

Other files in this repo are :-
- ~flake.lock~ so as to keep my versions intact. More on that later.
- ~assets/*~ contains images like the wallpaper that cannot be part of this.
- ~secrets/secrets.yaml~ contains encrypted keys and is edited using ~sops~.

Everything else in this repository is generated. They ideally shouldn't be edited directly.
There's also a github action that generates and commits these files if they do differ.

** Emacs + Org + Tangle
- [[https://www.gnu.org/software/emacs/][Emacs]] is the text editor that I use. Some people might take offense at me calling it a [[https://karl-voit.at/2015/10/23/Emacs-is-not-just-an-editor/][text editor]].
- [[https://orgmode.org/][Org mode]] is an inbuilt plugin for emacs that helps with managing org files like this one. Org files are similar to markdown but with [[https://www.youtube.com/watch?v=fgizHHd7nOo][superpowers]].
- Tangle is an org mode option that lets us export snippets to other files. In this case, the configuration snippets you see are written to individual files.
  - Anything that appears in ~<<code-id>>~ is like a variable that gets filled in later.
    You will see them in the snippets below where they are filled in by other snippets later in the file.
** Nix & Nixos
- [[https://nix.dev/][Nix]] is a bespoke programming language, used mainly to configure environments and dependencies.
- [[https://nixos.org/][Nixos]] is a linux distro where you define your operating system and other things using nix.
  The expectation is that the output of evaluating the nix files is a "configuration" that can be applied.
  This way your operating system is always defined by configuration files. You almost never install anything.
  Make a change to the configuration, reapply and repeat. You need vim? Add it to the config, and rebuild.

  ~YourNixCode(Input) -> System Configuration~

  I use [[https://nixos.wiki/wiki/Flakes][nix flakes]] which means that the entry point for the nix evaluation is a file called ~flake.nix~ which has two parts (among other things)

  #+begin_src nix
    {
      inputs: # describes the function input, consisting mainly of package sources
      outputs: # what the function outputs, a nixos configuration in our case
    }
  #+end_src

  Nix flakes is still behind an ~experimental~ flag, but it is considered the standard by most of the community.
  Flakes allow us to pin the input package versions using a ~flake.lock~ file.
  This prevents unwanted and surprise updates when rebuilding without changing the configuration.

* Flake Output
Now that the inputs are ready, the outputs define what the system will actually look like. I also define the machines that this configuration specifies early on. Finally, I iterate over the ~machines~ list and pull files from ~/.machines/${name}~ subdirectory. This allows me to have configuration that has machine specific configuration limited to those files while also keeping a modular reusable base.
We also add a devshell that makes editing this repository easier in emacs.

#+name: flake-outputs
#+begin_src nix :noweb no-export
  outputs = {
    self,
      nixpkgs,
      home-manager,
      emacs-overlay,
      sops-nix,
      catppuccin,
      nix-darwin,
      deploy-rs,
      disko,
      llm-agents,
      walker,
      ...
  }@inputs:
    let
      user = import ./user.nix;
      lib = nixpkgs.lib;
      machines = [
        "smallbox"
        "homelab"
      ];

      pkgs = import nixpkgs {
        inherit (user) system;
      };

      deployPkgs = import nixpkgs {
        inherit (user) system;
        overlays = [
          deploy-rs.overlays.default
          (self: super: { deploy-rs = { inherit (pkgs) deploy-rs; lib = super.deploy-rs.lib; }; })
        ];
      };

      macSystem = "aarch64-darwin";

      pkgsMac = import nixpkgs {
        system = macSystem;
      };
    in
      {
        nixosConfigurations = builtins.listToAttrs (
          builtins.map (machine: {
            name = machine;
            value = lib.nixosSystem {
              modules = [
                <<flake-emacs-module>>
                <<flake-config-module>>
                <<flake-home-module>>
                disko.nixosModules.disko             # disks
                sops-nix.nixosModules.sops           # sops
                catppuccin.nixosModules.catppuccin   # theme
              ];
              specialArgs = {
                hostname = machine;
                inherit user llm-agents;
              };
            };
          }) machines
        );

        <<macbox-module>>

        <<homelab-module>>

        devShells.${user.system}.default = pkgs.mkShell {
          buildInputs = with pkgs; [
            nil               # nix lsp server
            nixfmt            # nix formatter
            sops              # used to edit secrets
          ];
        };
      };
#+end_src

Lets look at the individual modules
1. Emacs
   The first is the emacs overlay so that it uses the nix-community emacs overlay from the inputs instead of the nixpkgs one.
   Overlays are a special nix way to override existing packages within a repository.

   #+name: flake-emacs-module
   #+begin_src nix
     ({ ... }: {
       nixpkgs.overlays = [ emacs-overlay.overlays.default ];
     })
   #+end_src

2. Then the machine specific configuration, in this case, just "smallbox".
   #+name: flake-config-module
   #+begin_src nix
     ./machines/${machine}/configuration.nix
   #+end_src

3. And finally the home-manager module.
   This can be initialized and managed on its own but I'd rather use the ~nixos-rebuild~ command to build everything instead of managing userland dotfiles separately.

   #+name: flake-home-module
   #+begin_src nix :noweb no-export
     home-manager.nixosModules.home-manager
     {
       home-manager.useGlobalPkgs = true;
       home-manager.useUserPackages = true;
       home-manager.extraSpecialArgs = {
         inherit user;
       };
       <<flake-home-backup>>
       <<flake-home-config>>
     }
   #+end_src

   - Home-Manager will not overwrite existing configuration files and that is good in most cases, but when everything is declarative like it is here, I'd rather that home-manager create a ~.backup~ and replace the file.
     #+name: flake-home-backup
     #+begin_src nix
       home-manager.backupFileExtension = "backup";
     #+end_src

   - Finally I pull in the machine specific home configuration. Along with the overrides from catppuccin.
     #+name: flake-home-config
     #+begin_src nix
       home-manager.users.${user.username} = {
         imports =  [
           ./machines/${machine}/home.nix
           catppuccin.homeModules.catppuccin
           walker.homeManagerModules.default
         ];
       };
     #+end_src

** Envrc + Direnv
Editing this file will be much nicer if we have the dev environment configured.
That is done in the devshells section. But to auto load this dev shell, we need a .envrc file.
This tells [[https://direnv.net/][direnv]] to load the devshell in the flake.
Finally, we also look for a .envrc-private file and try to load that. That contains devshell specific secrets.

#+begin_src nix :tangle .envrc
  use flake

  watch_file .envrc.private
  if [[ -f .envrc.private ]]; then
    source_env .envrc.private
  fi
#+end_src

* Machines
The individual machines subdirectory is configured as follows :-
#+name: tree
#+begin_src ditaa
  +--machine
  |  +--configuration.nix
  |  +--home.nix
  |  +--hardware-configuration.nix
#+end_src

- configuration.nix has the system configuration.
- home.nix has the user level configuration.
- hardware-configuration.nix has the unique hardware configuration.

~nixos-rebuild switch --flake .#smallbox~ looks for the smallbox configuration (in ~/machines/smallbox~)  and returns the configuration that is specific to that computer.

- Note about imports
  ~imports = []~ in a nix file will pull in the function/object from the list of files provided.
  This imported object (or function result) is just trivially merged into a common object.

** Login
Here we control what the login screen would look like. I'm using greetd's [[https://github.com/apognu/tuigreet][tuigreet]] for the ui.
Doesn't match the rest of the aesthetic of the system (with hyprland), but I like its simplicity.
The default session command starts the UWSM-managed Hyprland session explicitly. That keeps ~graphical-session.target~ active, which is what Home Manager graphical services such as Walker and Elephant attach to.

#+begin_src nix :tangle configuration/login.nix :noweb tangle :mkdirp yes
  { pkgs, user, ... } :
  {
    environment.systemPackages = with pkgs; [
      tuigreet
    ];

    services.greetd = {
      enable = true;
      settings = {
        default_session = {
          command = pkgs.lib.mkForce "${pkgs.tuigreet}/bin/tuigreet --remember --time --time-format '%I:%M %p | %a • %h | %F' --cmd '${pkgs.uwsm}/bin/uwsm start -e -D Hyprland hyprland.desktop'";
        };
      };
    };
  }

#+end_src

*** Agent Teams + DeepSeek Routing
Claude Code supports agent teams -- the lead session (Opus) spawns teammates in tmux panes. Each teammate is a full Claude Code process making its own API calls. By default they all hit Anthropic's API.

~CLAUDE_CODE_TEAMMATE_COMMAND~ overrides the binary used to spawn teammates. We use a wrapper script that reroutes teammate API calls to DeepSeek's Anthropic-compatible endpoint instead. The lead session stays on Anthropic (Opus), while teammates run on DeepSeek (cheaper, still capable for sub-tasks).

The wrapper:
1. Clears OAuth tokens (the lead uses OAuth, but DeepSeek needs an API key)
2. Sets ~ANTHROPIC_BASE_URL~ to DeepSeek's Anthropic-compatible endpoint
3. Sets ~ANTHROPIC_API_KEY~ from the sops-managed secret at ~/run/secrets/deepseek_key~
4. Rewrites ~--model~ to the DeepSeek model name
5. Execs the real ~claude~ binary

      };

      sourceRoot = "youwhatknow-${target}";
      nativeBuildInputs = [ pkgs.makeWrapper ];

      installPhase = ''
          install -Dm755 youwhatknow $out/bin/youwhatknow
          wrapProgram $out/bin/youwhatknow
        '';
    };

    claude-teammate = let
      claude-bin = llm-agents.packages.${pkgs.stdenv.hostPlatform.system}.claude-code;
      deepseek-model = "deepseek-v4-pro[1m]";
      deepseek-base-url = "https://api.deepseek.com/anthropic";
      secrets-path = config.sops.secrets.deepseek_key.path;
      teammate-prompt = ''
        CRITICAL: You are a teammate in an agent team. Your plain text output is NOT visible to anyone.
        You MUST use the SendMessage tool to communicate ALL results, findings, and status updates to the team lead.
        After completing your work, ALWAYS call SendMessage with to="team-lead" and your results as the message.
        If you do not call SendMessage, your work will be lost and nobody will see your output.
      '';
    in pkgs.writeShellScriptBin "claude-teammate" ''
      set -euo pipefail

      DEEPSEEK_API_KEY="$(cat ${secrets-path})"
      if [ -z "$DEEPSEEK_API_KEY" ]; then

          --model=*) continue ;;

        args+=("$arg")
      done

      args+=(--model "${deepseek-model}")
      args+=(--append-system-prompt "${teammate-prompt}")

      exec ${claude-bin}/bin/claude "''${args[@]}"
    '';
  in
  {

      gnhf

    environment.sessionVariables.CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS = "1";

    "Return the content under the first 'Active' heading in FILE as a string."

        (when (re-search-forward "^\\* Active" nil t)

  (defun wavefunk/org-set-todo-by-id (id state)
    "Find heading with CUSTOM_ID matching ID and set its TODO state to STATE.
     Searches all org files in `wavefunk/org-projects-dir'."
    (let ((files (directory-files wavefunk/org-projects-dir t "\\.org$")))
      (catch 'found
        (dolist (file files)
          (with-current-buffer (find-file-noselect file)
            (org-with-wide-buffer
             (goto-char (point-min))
             (while (re-search-forward
                     (format ":CUSTOM_ID:\\s-*%s" (regexp-quote id)) nil t)
               (org-back-to-heading t)
               (org-todo state)
               (save-buffer)
               (throw 'found (format "Set %s to %s in %s" id state (file-name-nondirectory file))))))
          (format "ID %s not found" id)))))

  (defun wavefunk/org-next-id (file prefix)
    "Return the next available PREFIX-NN id in FILE."
    (let ((max-id 0))
      (with-current-buffer (find-file-noselect (expand-file-name file))
        (org-map-entries
         (lambda ()
           (when-let* ((id (org-entry-get nil "CUSTOM_ID")))
             (when (string-match (format "^%s\\([0-9]+\\)$" (regexp-quote prefix)) id)
               (setq max-id (max max-id (string-to-number (match-string 1 id)))))))))
      (format "%s%02d" prefix (1+ max-id))))

  (defun wavefunk/org-add-task (file heading title prefix)
    "Add a TODO task with TITLE under HEADING in FILE with auto-assigned ID.
  HEADING is a top-level heading like \"Active\" or \"Backlog\".
  PREFIX is the project prefix like \"aw-\"."
    (let ((next-id (wavefunk/org-next-id file prefix)))
      (with-current-buffer (find-file-noselect (expand-file-name file))
        (goto-char (point-min))
        (if (re-search-forward (format "^\\* %s" (regexp-quote heading)) nil t)
            (progn
              (org-end-of-subtree t nil)
              (insert (format "\n** TODO %s\n:PROPERTIES:\n:CUSTOM_ID: %s\n:CREATED: %s\n:END:\n"
                              title next-id (format-time-string "[%Y-%m-%d %a]")))
              (save-buffer)
              (format "Added %s: %s under %s" next-id title heading))
          (format "Heading '%s' not found in %s" heading file)))))

  (defun wavefunk/org-query-all (state)
    "Return all tasks matching TODO STATE across all project org files."
    (let ((files (directory-files wavefunk/org-projects-dir t "\\.org$"))
          (results '()))
      (dolist (file files)
        (with-current-buffer (find-file-noselect file)
          (org-map-entries
           (lambda ()
             (when (string= (org-get-todo-state) state)
               (push (format "[%s] %s — %s"
                             (or (org-entry-get nil "CUSTOM_ID") "no-id")
                             (org-get-heading t t t t)
                             (file-name-sans-extension (file-name-nondirectory file)))
                     results))))))
      (mapconcat #'identity (nreverse results) "\n")))

    "Assign CUSTOM_IDs to all headings in FILE that lack one. Uses PREFIX."
    (with-current-buffer (find-file-noselect (expand-file-name file))
      (let ((count 0))
        (org-map-entries
         (lambda ()
           (unless (org-entry-get nil "CUSTOM_ID")
             (when (org-get-todo-state)  ; only assign IDs to TODO items
               (let ((next-id (wavefunk/org-next-id file prefix)))
                 (org-set-property "CUSTOM_ID" next-id)
                 (setq count (1+ count)))))))
        (when (> count 0) (save-buffer))
        (format "Backfilled %d IDs in %s" count (file-name-nondirectory file)))))

  mkWireguard = { address, privateKeyFile, peerPublicKeyFile, presharedKeyFile, endpointFile, allowedIPs, listenPort ? null }:
    let
      ips = builtins.concatStringsSep "," allowedIPs;
      routes = builtins.concatStringsSep "\n" (map (ip: "ip route add ${ip} dev wg0 2>/dev/null || true") allowedIPs);
    in
      {
        inherit address privateKeyFile;
        mtu = 1300;
        dns = [ "1.1.1.1" "8.8.8.8" ];
        postUp = ''

          preshared-key ${presharedKeyFile} \
          endpoint "$(cat ${endpointFile})" \
          allowed-ips ${ips} \
          persistent-keepalive 15
        ${routes}
      '';
        preDown = ''
        wg set wg0 peer "$(cat ${peerPublicKeyFile})" remove 2>/dev/null || true
      '';
      } // (if listenPort != null then { inherit listenPort; } else {});

  # CLAUDE.md

  This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

  ## Critical Rule

  ,**Never read or edit `.nix` files directly.** All `.nix` files are generated from `README.org` via org-babel-tangle. `README.org` is the single source of truth — every change must be made there. Edits to `.nix` files will be silently overwritten on next tangle.

  ## Commands

  ```bash
  # Tangle README.org into nix files (the CI workflow runs a more complete version with a startup block)
  emacs README.org --batch -f org-babel-tangle

  # Deploy to local machine
  nixos-rebuild switch --flake .#smallbox

  # Deploy to remote machines
  nix run github:serokell/deploy-rs -- .#macbox
  nix run github:serokell/deploy-rs -- .#homelab

  # Edit encrypted secrets
  sops secrets/secrets.yaml

  # Update flake inputs
  nix flake update

  # Format nix code
  nixfmt <file>

  # Enter dev shell (provides nil, nixfmt, sops)
  nix develop
  # or: direnv is configured via .envrc
  ```

  There are no tests or linters — validation happens at `nixos-rebuild` time.

  ## Architecture

  This is a literate NixOS configuration. `README.org` contains org-mode source blocks that tangle into all `.nix` files. Noweb references (`<<name>>`) compose fragments across blocks — understand how they assemble before changing structure.

  ### Machines

  - **smallbox** — primary workstation (x86_64-linux, NixOS, deployed locally)
  - **macbox** — work Mac (aarch64-darwin, nix-darwin, deployed via deploy-rs)
  - **homelab** — home server (NixOS, deployed via deploy-rs)

  ### Flake structure

  `flake.nix` dynamically generates `nixosConfigurations` by mapping over a machines list. Each machine imports `machines/<name>/configuration.nix` and `machines/<name>/home.nix`. Shared modules live in `configuration/` (system-level) and `home/` (home-manager).

  Key inputs: nixpkgs-unstable, home-manager, emacs-overlay, sops-nix, catppuccin, nix-darwin, deploy-rs, disko.

  ### Secrets

  Managed with sops-nix using age encryption. Key defined in `.sops.yaml`. Edit with `sops secrets/secrets.yaml`.

  ### CI

  GitHub Actions workflow (`.github/workflows/tangle.yml`) auto-tangles on push to `README.org` and commits the generated files.

  ### Others
  Also read AGENTS.md for more instructions.

      (message "running in %s" (buffer-file-name))

        (insert "# WARNING : This file was generated by README.org\n# DO NOT MODIFY THIS FILE!\n# Any changes made here will be overwritten.\n")

      (save-buffer))
    (add-hook 'org-babel-post-tangle-hook 'add-tangle-headers))
